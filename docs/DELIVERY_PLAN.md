## 2. 阶段划分

### A. 原型归一与契约

输出：PRODUCT、ARCHITECTURE、API、本计划；测量优先级、页号映射、题库来源和肖像授权风险。

验收：五份核心规格已纳入；首页取v2视觉方向，冲突机制仍取测量规范；三份Friends平行题和版本映射明确；所有静态示例与生产数据分离。

### B. 真实本地垂直闭环

交付链路：

1. 访客会话 → Self 8题 → 真实结果
2. Self结果 → 朋友链接 → 3个独立浏览器会话各3题 → 镜像
3. Today → 一次提交 → 低样本结果 → Journal
4. 真实答案 → Guess链接 → 另一个会话猜 → Reveal → Reverse
5. Guest → 用户名密码注册 → 原记录仍在 → 新浏览器真实登录
6. 重启服务 → 数据仍在

技术：Rust/Axum + SQLite迁移；React/TypeScript/Vite；同源cookie/CSRF；可配置服务地址；无假后端。

### C. 完成度与安全测试

必须覆盖：错误、越权、重复、并发、跨天、撤销、过期、身份升级、前后导航、移动显示。见第3节。

若依赖下载/编译/浏览器工具受限：先报告精确阻塞、哪些步骤未跑、已完成哪类检查。不能把受阻测试标通过，也不能仅以静态检查代替服务器运行。

### D. 受控试用准备（后续）

- 用户批准的可访问环境和域名，明确谁可访问
- HTTPS、备份/恢复、实际retention清理、错误监控
- 完整身份迁移；密码找回或真实OIDC/邮箱/微信提供商
- 正式数据说明、运营主体、隐私渠道、未成年人和滥用策略
- 人物/图片/字体商业权利确认或原创替代
- 英文完整题库审校、区域隔离与内容运营流程
- 真正跨设备邀请测试与安全审查

阶段D未完成不得称“生产上线可用”。接入、部署、发布都需独立授权。

### E. 100用户实验与生产演进（后续）

10–20人先测题目可懂性与60秒完成；30人看Self一致性、像不像反馈和朋友完成；100人再看真实D1/D3/D7、镜像与反向回路。所有指标来自真实事件，样本不足不下结论。

验证产品价值后再投入Postgres、多实例、管理后台、独立Social Inbox、通知、私有Who Knows Me Best列表和微信小程序。不能把这些延后项伪装成这次已实现的18页。
