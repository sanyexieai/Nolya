# Nolya 产品规格：从设计原型到可运行产品

版本：local-mvp-1 · 2026-10-19  
首发形态：移动优先响应式 Web · 中文优先  
后端：Rust / Axum · 本地持久化：SQLite  
状态：实现规格；实际通过的验证以交付验收报告为准

## 1. 产品定义

Nolya（诺芽）用生活中的小选择，让用户比较「我怎么选」「熟悉我的人觉得我会怎么选」和「对方能否猜中我的真实选择」。第一次使用不需要注册或朋友；社会互动是自愿的下一步。

四个核心回路：

1. Self：8 道真实生活二选一，形成有证据边界的自我基线
2. Friends：每位朋友答 3 个平行情境，比较朋友视角与自我基线
3. Daily Pulse：每天 1 个真实选择，保存为私人选择记录
4. Guess → Reveal → Reverse：猜一个已经保存的真实答案，提交后揭晓，再交换角色

产品不是心理诊断、人格测试、恋爱配对或公开评价平台。没有正确人格、道德评分、自由匿名文字、公开榜单、陌生人推荐、Feed、私信、打卡积分或虚构朋友反馈。首版不依赖大模型生成结论。

| 18 个设计包看似全产品 | 逐项对照原始 P0，标出合并和延后 | 两份 18 页编号不一致 |

## 3. 首版交付边界

### 本地 MVP 目标

- 真实 Rust HTTP API、SQLite 数据库、迁移与启动配置
- 访客 HttpOnly 会话，刷新/服务重启后保留已保存记录
- Self 完整 8 题、上一题修改、提交、真实结果及可选「像你吗」反馈
- 生成/复制有效朋友链接；三个独立浏览器会话各答三题；聚合镜像
- 今日题、先答后看、低样本诚实提示、真实选择记录
- 从真实保存答案创建 Guess、提交后揭晓、反向一步作答
- My Space 只显示真实 Self / Daily / Friends 状态
- 真实本地用户名密码保存账户；游客原地升级不丢数据
- 基础隐私说明、邀请撤销、数据导出/删除能力与限制披露
- 响应式移动体验、键盘操作、可恢复错误和最小端到端测试

“本地可运行”不等于“已公开上线”或“可直接用于真实规模用户”。邮件、短信、微信登录、微信 SDK、公开部署、域名接入、商业肖像、推送和支付均不在这次交付内。

### 原型尚不能保证、首版必须诚实的事项

- 一个浏览器会话不是一个被核实的真人。清 Cookie、换设备可以重新成为访客；本地试用不承诺抗女巫攻击
- 三个浏览器身份达阈值，只能称三份独立会话的回答。不可宣传「已验证三位真实朋友」
- 客户端分享或复制成功不证明对方收到/阅读；邀请链接本身是持有者可访问的凭证
- 本地 `localhost` 链接不能让远方朋友访问。跨设备试用需用户明确批准的可访问环境和正确公开地址
- 本地用户名不是已验证邮箱/手机，也不提供忘记密码恢复
- 首页/结果使用品牌装饰，不能暗示它是用户或朋友头像
- 双语只有已完成题库和 UI 审校才可宣称；中文内容不能伪装成完整英文版

## 4. 用户旅程与状态

### 4.1 第一次与 Self

首页「看看我会怎么选」→ 自动建立访客会话 → 8 道题 → 确认持久化 → Self 结果。

每题不预选，支持前后切换和改选。同页提交错误保留选择；页内上一题/下一题保留选择。离开此路由或刷新会清空未提交草稿，页面需明确告知；不把草稿写入共享浏览器存储。重复点击/重试不得新增重复结果。只在服务器确认后显示「已保存」。Self 页面不出现强制注册、强制邀请或虚构朋友数。

Self 结果最多两个稳定观察、一个真实的看场景提示，一句中性总结。如果四维都混合，直接呈现情境差异，不强造稳定标签。提供「邀请朋友」「看看今天」「保存账号」可选路径。

### 4.2 朋友视角

用户自愿创建链接时告知：链接持有者可看到昵称、相关题目并提交结构化选择；答案用于私人镜像。朋友进入时再次说明接收者、用途和第一位回答可能被推断的事实。无需通讯录、头像、真实姓名。

朋友只答服务端分配的 3 题；三位覆盖同样三个维度、不同平行版本。1 位：第一份观察；2 位：仍属有限观察；3 位：有条件的共识比较。没有朋友也能继续 Today 和 Journal。

不提供公开单人完整答案矩阵，不做自由文字，不能显示「猜对/猜错」。重复身份、自己答自己的邀请、超出三名额、跨题库版本、过期/撤销链接必须由服务器拒绝。

### 4.3 每日选择与 Solo

每天全站（本地首版 CN 区）一道题。未作答时，接口也不返回分布；答后才可看真实结果。N<50 只给定性提示或自己的选择，不展示精确百分比。

Journal 默认私有，只列真实记录；零条就为空，一条就只一条。不制造连续打卡、不随意回填过去日期。已回答题不可反复改票。

Solo 模式不需要朋友。积累七个不同作答日期后，针对明确显示的真实日期窗口，可呈现：

1. 与参与者最不同的一次：仅真实 cohort 样本≥50
2. 与参与者最一致的一次：同上
3. Self 呼应/差异：相同语义维度至少两次一致 Pulse 证据，并且原 Self 稳定

条件不足的卡片缺省/明确说明。七次不一定连续，不称连续七天；Pulse 永不改写 Self。

### 4.4 Guess、揭晓与反向

原回答者选一个已保存答案 → 生成有期限的链接 → 朋友看到题目和选项 → 一次提交 → 服务端保存并返回真实答案。

答案不能藏在可检查的 HTML、JSON、data 属性、URL、localStorage 或分享图里。前端仅隐藏元素不构成保密。未提交者不能读到别人已经取得的 Reveal。

揭晓主动作是交换角色。第一次使用的朋友可在原题上答自己的一次选择，再邀请原主人猜；不强迫做八题。这条独立记录不算完整 Self，也不冒充当天 Pulse。

关系记录少于 3 次只说「还在摸清彼此」，3–5 次展示实际命中次数，6 次以上可展示实际比值。所有计数基于独立来源答案，重复发同题不能刷理解度。

### 4.5 身份和保存

访客获得体验和有限连续性：当前浏览器 Cookie 可用时读取服务器记录，默认 30 天有效。不承诺永久、跨设备或无法恢复的游客身份。

本地账户使用真实用户名+密码与 Argon2id；原地升级同一用户 ID，保留所有记录。登录已有账户遇到游客数据合并尚未支持时，必须明确返回阻塞，保留原访客会话，不能静默丢数据。生产 OAuth/邮箱/微信是独立后续阶段。

## 5. 测量细则

| 维度 | A / +1 | B / -1 |
|---|---|---|
| D1 structure | 有计划 | 留空间、随性 |
| D2 directness | 直接表达 | 委婉处理 |
| D3 novelty | 尝鲜探索 | 熟悉稳定 |
| D4 expression | 情绪外显 | 自己消化 |

Self 每维两题取均值：+1/-1 稳定，0 看场景。目标维度按稳定优先，再 D1、D2、D4、D3 的确定性顺序补满三个。任何结果都记录题库版本、源答案和计算版本。

Friends 使用题目自己的显式 polarity 映射。B/C/D 的 A=+1、B=-1；D1-A 暂停使用且不擅自翻转。3 位同向=强观察共识，2 位同向=中等观察共识。Self稳定且与多数相同才能 alignment，相反才能 meaningful gap；Self混合时只描述观测，不下认知差结论。

这些阈值是产品表达的最低证据标准，不是经过临床验证的量表。首批用户反馈目标≥70%「很像+有点像」是实验参考，不能作为科学准确率宣传。

## 7. 数据、同意与隐私

- 用户的 Self、Pulse、Friends、Guess 四类事实分别存储；不能跨层覆盖
- 公开链接只有不透明 token，无顺序用户 ID、原答案、其他联系人或完整私密历史
- 普通访客无需手机号、邮箱、生日、通讯录、照片；首轮不采集年龄做统计
- 昵称为可选公开片段，在创建分享前显示会被接收者看到；HTML文本安全转义
- 每条外部分享由用户自己主动触发；不自动发消息、不自动邀请、不读取社交关系
- 朋友回答者可清除自己的数据，聚合随之重新计算；删除主人数据撤销关联链接
- 邀请撤销阻止未来访问/提交，但不谎称已发送信息能被收回
- 保留期限和导出删除说明使用实装事实。没有清理任务就不能宣称已自动物理删除
- 日志/统计只记录必要事件，不记录密码、Cookie、完整 token、原始答案或未经同意的个人身份
- 公测前补齐未成年人策略、滥用处理、数据区域/运营主体、可联系隐私渠道；本地开发资料不等于正式法律条款

## 8. 体验与发布质量

暖白底、鸢尾紫、柔和桃色，信息清晰优先。手机 320/390/430px 和桌面 1440px 不横向溢出。按钮≥44px；选中状态不只靠颜色；Tab/Enter/Space可用；异步状态读屏可感知；尊重减少动效偏好。

每条主链都有 loading、empty、ready、submitting、saved、error 状态。返回/刷新/重复点/网络失败/当天切换/过期撤销是正式功能，不是以后再修。API失败不能降级到截图示例数据。

## 9. 验证目标

首批目标是验证能否产生值得用户记住的真实认知差，而非追求虚荣活跃数字。建议实际记录 Self 完成、邀请创建、朋友完成、完整镜像、Pulse回答、Reveal、反向创建和真实 D1/D3/D7 回访。事件以数据库提交为准，不把按钮点击当成功。

实验证据不足就保留不确定性：不承诺「更懂你」，不保证朋友独立性，不将小样本包装为科学准确率。


## 2026-10-20 后续里程碑：访客与已有账户衔接

新增“验证已有账户 → 预览访客记录数量/阻塞 → 明确确认”的无冲突合并。预览不切换身份；确认成功才迁移全部记录、原邀请链接与参与身份，轮换会话并使访客旧会话失效。目标账户设置不被覆盖，分享链接将显示目标昵称，Self 保留原创建时间和 cohort。

当前不会解决同一天 Pulse 重叠、重复朋友/Guess 参与、跨身份自我互动或幂等键冲突。任何阻塞都会保留两个完整空间，不提供跳过记录或覆盖投票。取消、离页、过期、数据变化和提交失败均不得被显示成合并成功。此能力不能称为“完整身份迁移”。详细交互、隐私与验收见 [GUEST_MERGE.md](GUEST_MERGE.md)。
