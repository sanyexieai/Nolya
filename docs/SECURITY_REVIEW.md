# Nolya 本地 MVP 安全与数据完整性复核

日期：2026-10-19。最后一次 API 回归：04:13 UTC。范围：本地 Rust/Axum API、SQLite 数据模型与 React 关键状态管理；不包含公网渗透测试、部署、第三方身份服务或合规认证。

## 结论

`python3 tests/security_api.py --port 3011` 实际执行完成，退出码 **0**，**18 组针对性回归全部通过**。这证明下列具体接口和数据不变量在合成测试条件下成立，不代表全部安全风险已排除或已经可以生产上线。

脚本自行启动 Rust 二进制并创建全新临时 SQLite，只生成测试身份；某些测试直接修改这些临时 fixture，用于模拟旧版本、过期和七日期历史。测试期间会永久删除合成账户。脚本不接受外部服务地址或既有数据库路径，拒绝占用中的监听端口，退出时停止自身服务并清理临时数据库、日志与凭据。不得改为针对真实用户服务执行。

## 实际通过的 18 组回归

1. 未建立会话时，私有 Self、Mirror、Journal、Solo、Space、Export、邀请列表及 Guess 列表均拒绝访问
2. 他人的 Self assessment、反馈、邀请来源及 Guess 来源不可通过已知 ID 越权引用
3. 缺少 CSRF、错误 Origin 均拒绝写入；已有会话的登录也必须提供 CSRF
4. 重复问题、额外字段、不支持的题库版本、超出 32 KiB 的请求被拒绝；不兼容 Self 不能生成 Guess
5. 四个并发完全相同的幂等请求只生成一个 Self；相同 key 改变请求内容发生冲突
6. Guess 提交前不返回谜底；自猜被拒绝；提交后才揭晓；改猜拒绝；反向邀请只有原邀请人可参与
7. 对同一保存答案重复创建 Guess 不增加关系证据数量
8. 首次猜错后，撤回再重新分享相同答案不能把原有关系命中率刷成正确
9. Friends 撤回并重建链接不会让未完成的旧预约挤占三位参与者名额
10. 删除一位参与者会减少原邀请人的聚合人数，并允许新参与者使用释放的题型名额
11. Mirror 使用保存的题目极性元数据；不兼容的题库版本拒绝产生比较
12. Pulse 的 Journal、Guess 和 Today 保留保存时题目文案；不同题库版本与地区的群体计数不混合
13. Solo 不把窗口中途或之后完成的 Self 说成早先基线；严格按中国区窗口开始时间判断
14. Guest 注册保持身份和记录，同时旋转会话；旧会话失效；有记录的 Guest 登录既有账户安全拒绝且原 Guest 保持；导出不含密码哈希、会话哈希或 CSRF
15. 到期 Guess 的 GET 和新提交都被拒绝
16. 删除账户撤回其拥有或定向给它的链接、使会话失效、清除其他参与者缓存中相关的已揭晓答案，同时保留他人自己的 Self
17. 会话 Cookie 使用 256 位随机值、HttpOnly、SameSite=Lax；数据库保存 SHA-256 摘要；会话到期后读取和写入拒绝
18. 私有 API 响应含 no-store、nosniff、no-referrer、DENY 与禁止 framing 的 CSP

这里的“18 组”不是 18 个原子断言，每组包含多个检查。50 人样本边界、完整主流程及真实服务重启属于另一份 [E2E 验收记录](E2E_RESULTS.md)，不把其结果计入本次独立覆盖。

## 前端状态复核

已静态复核：

- Friends 和 Guess 的动态 token 路由按 pathname 重新挂载，避免 A 链接的已完成状态或揭晓显示到 B 链接
- Self 未提交草稿只保留在组件内存，不再使用跨身份、无版本的 sessionStorage 键；页面明确提示离开后不保留

后续实现已静态复核（04:13 UTC）：

- `Account.tsx` 提供 Guest 导出、二次确认退出后停留于已有账户登录模式，以及输入 DELETE 后删除 Guest；退出前明确提示可能失去访问与 JSON 尚不支持自动恢复
- `Guess.tsx` 在创建期间禁用来源选项；`Daily.tsx` 的查询依赖当前 user ID
- `session.tsx` 使用单飞 Promise 合并同时发生的 Guest bootstrap

以上是静态复核，未在本次安全脚本中模拟真实浏览器点击。快速重复点击、返回、路由切换及数据下载的浏览器证据仍以最终 UI 测试为准，不计入 API 18 组通过结果。

## 仍存在的本地开发边界

- 多 Cookie/设备仍能创建不同 Guest，不能证明是不同真人。内存限流和三槽约束不等于生产反滥用系统
- 本地用户名密码登录没有找回、验证邮箱、MFA 或真实微信/OIDC；已有账户和有数据 Guest 的完整合并尚未实现，当前明确拒绝并保留数据
- 自动清除过期 Guest、会话、历史幂等缓存与备份保留规则尚未实现。到期访问拒绝不等于底层数据自动删除
- 本轮未验证真实 HTTPS、反向代理、生产 Cookie 配置、TLS、跨设备/多实例行为、备份恢复和依赖漏洞清单
- 本轮没有证明所有历史版本可继续计算；不兼容 Self/朋友题库会安全拒绝。生产题库更新必须提升版本并具备迁移/兼容策略
- 独立端点审查不能替代最终 UI、可访问性、所有中断状态与完整产品验收

## 安全复现

在项目根目录先构建当前代码：

```sh
cargo build --manifest-path backend/Cargo.toml
python3 tests/security_api.py --port 3011
```

省略 `--port` 会选择空闲本地端口。可用 `--binary` 指向另一个已构建的本项目二进制；不能传入服务 URL 或数据库。服务器和测试在同一进程命名空间执行。输出只显示组名与断言摘要，不输出账户密码、Cookie、邀请 token 或原始数据内容。

## 2026-10-20 补充：显式无冲突身份合并

首版的普通登录安全 409 保持。新增密码验证预览及一次性确认接口后，合并行为以 [GUEST_MERGE.md](GUEST_MERGE.md) 为准；并未实现覆盖投票或丢弃重复参与的完整冲突解决。

原 18 组安全回归在本轮再次通过，另有 35 个隔离合并 HTTP 用例和 4 个新增 Rust 单元测试通过，详见 [MERGE_VERIFICATION.md](MERGE_VERIFICATION.md)。覆盖源会话/目标凭据重新检查、CSRF/Origin、五分钟 session-bound 摘要 token、数据变化/到期/重放、完整图迁移、跨身份变自我互动阻止、幂等保护、并发、SQL 失败回滚、导出/删除与既有链接隐私。

代码复核后修复并回归了两类细节：迁移不能直接丢弃 Self 幂等键；已完成的外部朋友邀请撤回也必须使预览失效。合并后只清空失效响应体并保留键和摘要；Self 创建响应继续返回同一保存结果。

浏览器实测仍受沙箱启动限制，DOM 模拟的组件检查不补足真实浏览器证据；生产边界不因本轮 API 检查通过而改变。
