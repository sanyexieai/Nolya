# Nolya 产品化验收清单

本轮目标：从本地原型推进为具备完整使用流程、账户自助维护、安全数据处理与可部署交付物的单机 Web 产品。后端 Rust + Axum，SQLite 持久化；中文、手机优先。

## 定义和边界

“功能实现”“自动化回归通过”“真实浏览器验收”“公网部署”是四个独立状态。只有前三者满足才可以称该范围的发布候选已完整验收；公网部署另外需要明确环境与授权。当前浏览器受环境阻塞，不将本轮称为已全面验收的生产产品。

## 工程验收范围

| 领域 | 本轮实现 | 验收证据 |
|---|---|---|
| 核心闭环 | Self、三位朋友镜像、每日选择、猜测揭晓/反向邀请、账户、无冲突访客合并 | 原安全/合并 HTTP；完整主流程和实际重启 |
| 邀请管理 | 两类链接独立分页、状态/过期/完成数、复制和撤销；历史链接不再静默截断 | product_api、组件测试；真实点击待验 |
| 历史使用 | 日记起止日期/选择筛选及稳定分页；自我观察历史和维度比较 | product_api、组件测试；不将少量差异解释为人格变化 |
| 账户维护 | 旧密码验证后改密，全部会话撤销，生成一次性恢复码，恢复后正常登录/合并，删除前再验证密码 | auth_security_api；恢复码仅保存摘要，不冒充邮箱/真人验证 |
| 会话安全 | 密码变化/恢复撤销旧会话；事务内复核有效会话，避免已撤销会话继续提交；CSRF/Origin/请求限流 | auth/security/merge 回归 |
| 数据可靠性 | 事务、请求幂等、SQLite 在线备份、校验、非覆盖恢复、真实 API 恢复与重启 | scripts/ops 测试；生产备份计划待运营配置 |
| 配置/运行 | 生产启动失败关闭、精确 HTTPS Origin、Secure Cookie、1–30 天会话、SIGTERM、健康/就绪探针 | config_api、Rust 单测、restart_e2e |
| 交付 | 源码、Linux x64 启动包、部署示例、CI 与回滚说明 | 本轮验证报告和文件摘要 |

最终精确通过数量以 RELEASE_VERIFICATION.md 为准。不能把表中实现描述当作真实浏览器或生产环境证据。

## 仍需真实环境完成的发布门槛

1. 真实浏览器点击、320/390/430/1440px 布局、键盘和读屏、刷新/后退/取消/重复提交，以及多身份和跨设备邀请。当前云浏览器与执行器 localhost 不互通，独立 Chromium 受沙箱限制；未绕过限制。
2. 拟上线环境的 HTTPS、域名、边缘限流、代理超时、备份调度/异地存储、恢复演练和告警。当前没有实际部署，也未声称模板已经在目标环境验证。
3. 运营主体、隐私联系渠道、服务协议与适用法规审定。内置隐私/帮助为事实性产品说明，不是法律审查意见。无真实邮件或微信集成。
4. 本地用户名是账户标识，不是验证邮箱或独立真人身份。恢复依赖用户预先保存的恢复码；若密码和恢复码同时丢失，没有管理员绕过或虚构找回渠道。
5. 单进程 SQLite 的适用范围是小规模单机服务。全局安全限流不是完备的真实人群防刷，不能保证大规模、多实例或高可用。
6. 访客合并遇到冲突保留双方数据并停止，尚无冲突择优覆盖工具。界面须说明解决路径，不偷偷丢弃任何一方。
7. Docker、Caddy、systemd 运行验证受本环境能力限制；可执行 Linux 包与 API 测试不替代容器部署演练。
