# 真实 API 验收计划

用 Python 标准库 HTTP 客户端和独立 CookieJar 模拟一个 owner、三个不同朋友及一个无关访客。禁止 mock 服务。运行结果只表示该运行实际验证的场景；重启持久化须实际重启同数据库服务后再执行续验。

## 核心流程
1. 各身份独立建立会话；获取Self题库，确认8题、4维各2题。owner提交8答，返回有限确定性画像。
2. owner发起朋友邀请。本人不能为自己填；三个朋友分别得到3个平行题并提交。1、2人不解锁完整共识；3人才完成真实镜像。重复不能增加人数，跨身份不能读owner私有结果。
3. Pulse未答不能读取分布。提交后读取真实计数；小样本不出现精确百分比。同身份重复不能增加票数，修改已提交答案应拒绝或保持原结果。
4. owner从已答题发起Guess，未答题不能发起。朋友读取时无真实答案或is_correct。提交后才揭晓，由服务端判定。重复相同提交不增记录，冲突提交不改原答案；伪造身份、猜他人的提交标识不可泄密。
5. 游客升级账户后原Self、邀请与Pulse数据仍存在；安全失败时不能半合并。

## 持久化
脚本保存本轮随机标识和测试Cookie到临时状态文件（含会话凭据，不提交版本库）。停止服务，使用同数据库启动后，续验Self、镜像、Pulse、Guess结果。不能用只重复GET代替重启。

## 证据
记录每个断言、HTTP状态和失败摘要，不打印Cookie、邀请token、密码或敏感原始回答。退出码非零代表失败。CI应隔离数据库并清理测试数据，不能对生产真实用户执行。

## 对抗与并发
- 第四位朋友到达时，首三位聚合必须保持稳定，或按明确规则拒绝；并发抢占不能造成重复槽位/超限。
- 同一身份重复创建反馈会话不得占据多个朋友名额。仅能证明服务端cookie身份去重，不能宣称真人去重；换设备/清cookie仍是已知反作弊边界。
- 发起者不能猜自己。撤销/过期邀请不能获取答案。
- owner重做Self后，既有campaign仍使用冻结旧attempt，不污染已有镜像。
- 未实现接口按remaining记录，不跳过后宣称测试通过。
